# kojiPDFviewer — 日本語仕様書

**対象版**: 現行ソース（2026-09-26 時点）

**目的**: アプリの動作を利用者・引き継ぎ担当者が読むための説明。新機能の要求や開発タスクを定義する文書ではありません。
**確認範囲**: ソースコードと README の確認。実際のメール PDF、Outlook、MSI を使った総合動作確認は含みません。

## 1. アプリの目的

「KojiPDF」などで複数のメールを一つにまとめた PDF を、メール単位で探して読む Windows 用デスクトップアプリです。メール形式でない一般資料 PDF も開けます。PDF の内容を編集するアプリではありません。

## 2. 対応する PDF

| 種類 | 判定と表示 |
| --- | --- |
| メール束 PDF | ルートしおりの多くが `名前_開始ページ_ページ数` 形式で、先頭のメールページに件名・差出人・受信日時などの見出しがある場合。メール一覧と PDF を並べて表示します。 |
| 一般資料 PDF | 上記の条件に合わない場合。PDF のしおりを階層ツリーとして表示します。 |
| しおりのない PDF | 一般資料モードで開きます。しおり一覧は空です。 |

画像だけの PDF を文字認識する OCR 機能はありません。検索は PDF から抽出できる文字が対象です。

## 3. PDF の開き方と画面

- 「PDFを開く」で複数ファイルを選べます。PDF のドラッグ＆ドロップ、起動時のファイルパス指定にも対応します。
- 複数の PDF をタブで開けます。同じ PDF を再度指定した場合は、開いているタブに移動します。
- Pythonコードからの起動時も、メイン画面と別ウィンドウにアプリアイコンを表示します。アイコンは黄色い図形に青い「koji」と赤い「PDF」を重ねたデザインです。
- 起動時の開始画面には、操作案内、お気に入り、最近使った PDF が表示されます。「+」タブから開始画面を開けます。
- ページ送り、幅に合わせる表示、ページ全体表示、全画面表示ができます。左側の一覧は表示・非表示を切り替えられます。
- 上部の現在ページ番号は入力欄です。ページ番号を入力してEnterを押すと、そのページへ移動します。Ctrl+Gで入力欄を選択できます。Escまたは欄からフォーカスを外すと入力を取り消します。1から総ページ数までの整数のみ指定でき、範囲外や数字以外では移動しません。しおりのないPDFでも使用できます。
- メール一覧の上部にある「しおり一覧へ」で、同じPDFをしおり一覧表示に切り替えられます。しおり一覧上部の「メール一覧へ」でメール一覧表示に切り替えられます。切り替え前のページとタブ位置は維持されます。
- しおり一覧でしおりを選んで「メール一覧へ」を押すと、選んだしおりの直下を一覧表示します。右クリックからは「直下」または「配下すべて」を指定できます。メール一覧上部の「対象」で別のしおりや「PDF全体（ルート）」を選べます。「PDF全体（ルート）」は従来どおり第1階層の一覧です。
- PDFに埋め込まれたページリンクをクリックすると、PDF内の指定ページへ移動します。Webリンクは既定のブラウザー、`mailto:` は既定のメールアプリ、`file:` は既定のアプリで開きます。日本語を含むファイルリンクもPDF内の元文字列から読み取り、相対パスはPDFのあるフォルダを基準にします。リンク先のファイルがない場合はメッセージを表示します。

## 4. メール束 PDF の閲覧

- 一覧には件名、差出人、宛先、受信日時、本文冒頭、添付ファイルなどが表示されます。
- しおりを対象にした一覧では、メールと判定できないしおりは資料行としてタイトルとページ範囲を表示します。資料行ではページ移動、別ウィンドウ表示、印刷、PDF保存ができます。返信と既読操作はメール行だけにあります。
- 一覧でメールを選ぶとそのページへ移動します。PDF 側でページを移動したときも、対応するメールが一覧で選ばれます。
- 受信日時・件名・差出人で並べ替え、昇順・降順の切り替えができます。
- 返信・転送の接頭辞を除いた件名でグループ化できます。グループの見出しは折りたたみ可能です。
- メールを表示すると既読になります。右クリックで既読・未読を切り替えたり、一括で既読にしたりできます。
- 添付ファイルの表示をクリックすると、PDF 内の該当ページへ移動します。添付元の別ファイルを抽出する機能ではありません。
- `.msg`・`.eml` の添付は、添付名から番号・サイズ・拡張子を除いた文字列を、該当メールの添付しおり名と照合して移動先を決めます。一意に決まらない添付だけ赤く表示し、押してもページを移動しません。

## 5. 検索

- メール束 PDF では件名、差出人、宛先、CC、本文、添付ファイル名を検索します。検索結果は選択中の対象と範囲で絞られます。資料行のタイトルも検索対象です。
- 一般資料 PDF ではしおりタイトルと、その区間から抽出した本文を検索します。
- 検索には PDF ごとに作成する SQLite の全文検索インデックスを使います。

## 6. 一般資料 PDF の閲覧

- しおりを階層のまま一覧に表示します。選択すると該当ページに移動します。
- 開いた直後は最上位のしおりだけを表示します。しおり一覧上部の「＋ 数字 −」で表示する階層数を1段ずつ増減できます（最上位が1）。「全展開」は最大階層、「全折り」は1にします。検索中は階層操作を無効にし、検索解除後に元の階層数へ戻します。
- 検索中は該当するしおりを、上位見出しの情報付きで一覧表示します。
- しおりで区切られた範囲を別ウィンドウで開いて比較できます。

## 7. 印刷・保存・別ウィンドウ

- メールや添付ファイル、一般資料のしおり区間など、対象となるページ範囲を印刷できます。
- ページ範囲を別の PDF として保存できます。元の PDF のページは変更しません。
- メールまたはしおり区間を独立したウィンドウで開き、他の箇所と見比べられます。
- 別ウィンドウでもページ番号を直接入力できます。番号はそのウィンドウに切り出したPDF内の1ページ目から数えます。

## 8. Outlook 返信下書き

メール一覧から「返信」または「全員に返信」を選ぶと、PDF に記載された差出人・宛先・件名・本文を使って Outlook の下書きを作成します。送信は行いません。Windows 版 Outlook デスクトップと、判別できる差出人メールアドレスが必要です。これは元メールの Outlook アイテムを開く機能ではなく、PDF の情報から新しい下書きを組み立てる機能です。

## 9. 保存される情報

- PDF と同じフォルダに、メール用の `<PDFファイル名>.index.sqlite3` と、しおり用の `<PDFファイル名>.document.index.sqlite3` を必要に応じて作成します。したがって PDF の置き場所への書き込み権限が必要です。
- PDF のサイズや更新日時が変わると、利用するモードのインデックスを作り直します。ツールバーから再作成もできます。
- メール添付のページ対応ルールや階層対象の索引形式が更新された旧インデックスは、次の読み込み時に自動再作成します。保存済みの第1階層メールの既読状態は引き継ぎます。
- 最近使った PDF とお気に入りのパスはアプリ設定として保存されます。
- 旧アプリ名の設定がある場合、最近使った PDF とお気に入りは新しい設定へ引き継がれます。
- インデックスには本文や宛先などの情報が含まれるため、PDF と同様に取り扱ってください。

## 10. 操作の目安

| 操作 | キー |
| --- | --- |
| 検索欄へ移動 | Ctrl+F |
| 左側の一覧を表示・非表示 | Ctrl+B |
| 前・次のページ | ← / → |
| 全画面表示を切り替え | F11 |
| 全画面表示から戻る | Esc |

ツールバー左端のボタンは、一覧の表示状態に応じて「一覧を隠す」「一覧を表示」に切り替わります。全画面表示中は Ctrl+B または PDF 上の右クリックメニューから切り替えられます。

## 11. 配布形態

ソースからの実行には Python 3.12 と `requirements.txt` の依存パッケージが必要です。`master` への push で GitHub Actions が Nuitka の standalone アプリを WiX で MSI 化します。ビルドが成功した後、別の Release Action にリリース名を入力して実行すると、同じコミットの MSI を VirusTotal で確認し、GitHub Release と版番号のタグを作成します。MSI は全ユーザー向けにインストールされ、スタートメニューに項目を作成します。
