# Feature Specification: しおりを対象にしたメール一覧

**Created**: 2026-09-26

**Status**: Implemented

**Input**: 選択したしおりの直下または配下すべてをメール一覧にし、従来の第1階層一覧にも戻れるようにする。

## User Scenarios & Testing

### User Story 1 - 選択したしおりを見る (P1)

しおり一覧で添付フォルダなどを選び、その子をメール一覧形式で閲覧する。

**Acceptance Scenarios**:

1. しおりを選んで「メール一覧へ」を押すと、そのしおりの直下の子が表示される。
2. 右クリックから直下または配下すべてを選べる。
3. 範囲を配下すべてに変えると孫以下も表示される。

### User Story 2 - 従来の一覧へ戻る (P1)

対象メニューから「PDF全体（ルート）」を選ぶと第1階層の従来の一覧に戻る。

### User Story 3 - 資料が混在する (P2)

メールと判定できないしおりはタイトルとページ範囲を持つ資料行として表示し、ページ移動、別ウィンドウ、印刷、保存ができる。返信と既読操作はメールだけに適用する。

## Edge Cases

- 子のないしおりを対象にすると空の一覧と0件を表示する。
- 検索と並べ替えは現在の対象内で働く。
- PDFを編集せず、索引再作成で従来のルート既読状態を引き継ぐ。

## Requirements

- **FR-001**: しおり選択から直下を一覧表示できる。
- **FR-002**: 配下すべてへ切り替えられる。
- **FR-003**: PDF全体（ルート）で従来の第1階層一覧へ戻れる。
- **FR-004**: 対象と範囲を一覧上部に表示する。
- **FR-005**: メールと資料を区別して表示・操作する。
- **FR-006**: 検索、並べ替え、ページ移動、既読状態、添付操作を対象切り替え後も維持する。

## Success Criteria

- 合成PDFの直下、全配下、ルートの3条件で期待するしおり集合と件数が一致する。
- 資料行から返信を開始できず、メール行からは従来の返信操作ができる。
- 既存のメール閲覧・しおり閲覧の回帰テストが通る。

## Assumptions

- メール判定はしおり名のページ形式と先頭ページのメール見出しに基づく。
- ルートでは従来どおり第1階層を表示する。
