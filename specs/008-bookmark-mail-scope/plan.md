# Implementation Plan: しおりを対象にしたメール一覧

## Context

`parser.py` のメール抽出はルート限定。`db.py` のメール索引も親子関係を持たない。`main.py` はメールと資料を別のタブ型で描画する。

## Design

1. すべてのしおりをメール索引に取り込み、TOC位置、親TOC位置、階層、メール判定を保持する。第1階層の行IDを維持して既読を引き継ぐ。索引バージョンを上げて旧版を再構築する。
2. 対象の子孫を親関係から求め、検索・並べ替え結果に適用する。ルートは第1階層だけを選ぶ。
3. しおり一覧の選択と右クリックから対象を渡し、メール一覧上部に対象・範囲を配置する。
4. 資料行を区別して描画し、返信・既読を提供しない。ページ移動、別ウィンドウ、印刷、保存は共通化する。
5. 合成PDFとGUIテストで階層、資料混在、ルート復帰を確認する。検証後に読者向け仕様書を更新する。

## Data and compatibility

元PDFは変更しない。派生SQLite索引は再構築される。ルート行IDの保持により既存の既読状態を引き継ぐ。添付リンクは既存の抽出処理を使う。
