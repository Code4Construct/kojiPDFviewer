# Feature Specification: .msg/.eml 添付のページリンク

**Created**: 2026-09-26
**Status**: Approved for implementation
**Input**: 添付ファイル名の番号接頭辞、`.msg` / `.eml` 拡張子、末尾のサイズ表記を除いた文字列を含むしおりを添付リンクに紐付ける。一意に見つからない添付だけ赤く表示し、リンクを持たせない。

## User Scenarios & Testing

### User Story 1 - メール添付を開く (Priority: P1)

利用者は、名前が日時・送付者・件名形式へ変換された `.msg` / `.eml` 添付のチップを押し、その添付のPDFページへ移動できる。

**Acceptance Scenarios**:

1. 添付名から先頭番号、末尾サイズ表記、拡張子を除いた文字列を含むしおりが、現在のメールの添付フォルダ内に1件ある場合、その開始ページへ移動する。
2. 対応しおりがない、または複数ある場合、その添付だけ赤く表示され、押してもページは移動しない。
3. 通常添付のリンク、添付名の表示、メールの既読状態は維持する。

### Edge Cases

- `.MSG` / `.EML` の大文字表記も対象にする。
- `.msg` / `.eml` のしおりに子しおりがあっても、親の開始ページに紐付ける。
- 添付名の順番とPDFページ順が異なる場合に誤って紐付けない。
- 対応先不明の添付は、オーバーフローメニューでも無効にする。

## Requirements

- FR-001: `.msg` / `.eml` の添付は、指定の文字列照合で一意の開始ページを得る。
- FR-002: 一意に特定できない添付のみ、赤い非リンクのチップとして表示する。
- FR-003: 通常添付の既存のページ対応を維持する。
- FR-004: 既存インデックスは再構築し、既読状態を維持する。元PDFは変更しない。

## Success Criteria

- SC-001: 合成PDFで `.msg`、`.eml`、通常添付、未一致、重複の５ケースが期待するページ状態になる。
- SC-002: 未一致の添付だけが赤い非リンクになる。
