# Implementation Plan: .msg/.eml 添付のページリンク

**Date**: 2026-09-26 | **Spec**: [spec.md](spec.md)

## Summary

`parser.py` で添付ごとに候補しおりを判定する。`.msg` / `.eml` は番号・サイズ・拡張子を除いた文字列を添付フォルダ直下のしおり名に含むか調べ、一意ならその親しおりの開始ページを用いる。通常添付は既存の位置対応を基準にし、混在ケースでは名前・番号が確認できる候補だけを紐付ける。`main.py` はページ位置不明の添付チップを赤く描画する。

## Data and Compatibility

`db.py` のメールインデックスに抽出規則の版を保存する。旧版は次回閲覧時に自動再作成し、既読IDを引き継ぐ。PDFと既存設定は変更しない。

## Verification

`parser.py` の合成しおりツリーと、一時フォルダの合成PDFで `.msg` / `.eml` の子階層、順番違い、通常添付、重複・未一致、保存済み既読状態を確認する。GUIで赤いチップとクリック不可を確認する。実際の私的メールPDFはGitへ含めない。

実施結果: 合成PDFで `.msg` / `.eml` と通常添付のページ対応、重複・未一致を確認。旧インデックスの再作成と既読状態の保持、赤いチップの描画とクリック抑止をオフスクリーンGUIで確認。実際のKojiPDF生成PDFによる目視確認は未実施。

## Constitution Check

既存のPDF読み込み・検索・ページ範囲と既読状態を維持する。日本語のUTF-8を保ち、検証後に読者向け仕様書を更新する。
