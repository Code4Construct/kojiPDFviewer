# 現行動作の基準仕様

**状態**: 現行コードから記録した基準（新機能の要求ではない）

**作成日**: 2026-09-23
**対象**: `main.py`, `parser.py`, `db.py`, `outlook_reply.py`

## 利用場面と受け入れ条件

### 1. メール束 PDF を読む

利用者が KojiPDF 形式のメール束 PDF を開くと、アプリはしおりと先頭ページの見出しからメール形式を判定し、メールの一覧と PDF を表示する。

- PDF 選択ダイアログ、ドラッグ＆ドロップ、コマンドライン引数から開ける。
- 件名、差出人、宛先、日時、本文の冒頭、添付ファイルを一覧で確認できる。
- メールを選ぶと該当ページへ移動し、PDF 側のページ移動も一覧に反映される。
- 件名、差出人、宛先、本文、添付名を検索できる。
- 同じ件名のグループ表示、並べ替え、既読・未読の管理ができる。

### 2. 一般資料 PDF を読む

メール形式の条件を満たさない PDF を開くと、一般資料モードでしおりを階層表示する。

- しおりを選ぶと該当ページへ移動する。
- しおりタイトルと本文を検索できる。
- しおりがない PDF も一般資料として開ける。ただし、しおり一覧は空になる。

### 3. ページ範囲を利用する

- メール、添付、しおり区間を別ウィンドウで開いて閲覧できる。
- 対象区間を印刷できる。
- 対象ページを別 PDF に保存できる。元 PDF は変更しない。

### 4. Outlook 返信下書きを作る

- メール一覧の操作から返信または全員返信の下書きを開ける。
- Windows 版 Outlook デスクトップが必要。アプリは送信を行わない。
- 差出人アドレスを特定できない場合は、下書きを作成せずエラーにする。

### 5. 利用状態を再利用する

- PDF の隣に `<PDF名>.index.sqlite3` を作成し、本文検索用データを再利用する。
- PDF のサイズ・更新日時、またはモードが変わればインデックスを再作成する。
- 最近開いた PDF とお気に入りを開始画面で表示する。

## 境界条件

- メール判定は、ルートしおりの 8 割以上が `名前_開始ページ_ページ数` 形式であり、先頭メールのページに必要な見出しが 2 種類以上ある場合に成立する。
- 検索対象は PDF から抽出できるテキストである。画像のみの PDF に OCR をかける機能は現行コードにない。
- インデックスは PDF と同じフォルダに書くため、そのフォルダに書き込み権限が必要である。
- 実際のメールデータを含む PDF は Git に登録しない。

## 確認方法

合成したメール束 PDF、しおり付き一般資料 PDF、しおりなし PDF でモード判定・一覧・検索・ページ移動を確認する。印刷、Outlook、MSI は Windows 上で個別に確認する。この文書はコード調査による基準であり、実データによる総合確認結果ではない。
