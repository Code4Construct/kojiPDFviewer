# MSI インストール体験

## ユーザーシナリオ
- インストール後、スタートメニューとデスクトップの両方から kojiPDFviewer を起動できる。
- インストール先にはアプリと README.md、LICENSE、THIRD_PARTY_NOTICES.md が配置され、アンインストール時には MSI が配置した項目が削除される。

## 要件
- FR-001: 既存の全ユーザー向け MSI とスタートメニュー項目を維持する。
- FR-002: 全ユーザーのデスクトップに起動用ショートカットを作成する。
- FR-003: README.md、LICENSE、THIRD_PARTY_NOTICES.md をアプリのインストール先に配置する。
- FR-004: ショートカットと FR-003 の文書はアンインストール時に削除する。
- FR-005: 参照先の製品名、UpgradeCode、版番号は転用しない。
- FR-006: 参照先と同じ GNU AGPL v3 の正式全文を同梱し、インストール時に表示する。
- FR-007: インストール先を選択でき、完了時に README.md を開く選択肢を表示する。
- FR-008: 本体ライセンスと Python/Qt 依存物の条件を分けて説明し、第三者告知を MSI に同梱する。
- FR-009: LICENSE とインストール画面には日本語の案内と AGPL v3 の無改変の英語原文を表示し、第三者の条件は同梱文書へ案内する。

## 受け入れ条件
- WiX ビルドが成功し、MSI のインストール、起動、アンインストールで上記項目を確認できる。
- Nuitka、VirusTotal 検査、`VERSION` と `v<VERSION>` タグの関係を維持する。
- README と第三者告知のライセンス表記が、依存物のパッケージメタデータと上流の一次資料に矛盾しない。

## 範囲とリスク
対象は `LICENSE`、`THIRD_PARTY_NOTICES.md`、`README.md`、`installer/kojiPDFviewer.wxs`、WiX 表示用 RTF と MSI ビルド手順。参照先と同じ AGPL v3 を採用する。製品固有の名前、UpgradeCode、版番号は維持する。既存ユーザーの環境ではデスクトップショートカットが追加される。実際の依存物はビルド時に変わり得るため、生成物の告知はリリースごとに確認する。
